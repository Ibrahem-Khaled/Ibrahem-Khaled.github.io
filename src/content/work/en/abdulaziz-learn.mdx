## 01 · Context

Abdulaziz Learn is an interactive e-learning platform where students receive on-demand audio-visual explanations synchronized to curriculum slides and exercises. The initial prototype relied entirely on commercial third-party LLM APIs.

As concurrent student usage grew, two problems threatened unit economics:
1. **Linear per-token cost explosion:** Arabic text tokenizes less efficiently than English on many commercial tokenizers, multiplying API bills on long multi-step lesson explanations.
2. **Unpredictable latency:** Waiting for full commercial responses before synthesizing audio created multi-second pauses that broke the interactive classroom feel.

## 02 · Constraints

- **Zero downtime migration:** Active students could not experience broken lessons while swapping the inference backend.
- **Strict pedagogical format:** Output had to emit structured Arabic explanations paired with exact visual step markers (so slide transitions stayed locked to spoken audio).
- **Private curriculum data:** Client ownership required keeping fine-tuning datasets and inference endpoints off third-party training pipelines.

## 04 · Key Engineering Decisions & Trade-offs

| Decision | Alternatives Considered | Why This Won |
|---|---|---|
| **Self-Hosted Fine-Tuned Qwen (OpenAI-Compatible Serving)** | Staying on commercial APIs with shorter prompts, or switching to a smaller zero-shot model | Fine-tuning Qwen on domain-specific Arabic curriculum pairs let a compact model match explanation quality while exposing an OpenAI-compatible HTTP interface — minimizing Laravel orchestrator changes and capping infrastructure to a fixed GPU cost. |
| **Redis Semantic Cache Before GPU Queue** | Hitting the GPU for every student request | In curriculum-driven education, hundreds of students ask near-identical questions on the same lesson slide. Caching normalized `(lesson_id, intent_hash)` explanations in Redis served repeat requests in milliseconds and freed GPU capacity for novel questions. |
| **Chunked SSE Streaming + Step Markers** | Blocking until full explanation completes | Streaming sentence-level JSON chunks with explicit `[STEP:n]` markers allowed audio synthesis and visual highlights to begin on the first sentence instead of waiting for the entire lesson script. |
| **Circuit-Breaker Fallback to Commercial API** | Hard cutover with no fallback | During exam-week traffic spikes, GPU queue saturation could degrade UX. A simple circuit breaker automatically overflows excess traffic to the commercial API only when GPU queue wait exceeds threshold, preserving SLA without paying commercial rates at baseline. |

## 05 · Inference Router with Circuit Breaker (Excerpt)

A condensed version of the routing service that checks the semantic cache, prefers the self-hosted Qwen node, and fails over cleanly only on timeout or overload:

```python
from dataclasses import dataclass
import hashlib
import httpx

@dataclass
class InferenceConfig:
    qwen_base_url: str
    fallback_base_url: str
    timeout_seconds: float = 4.5

class ExplanationRouter:
    def __init__(self, config: InferenceConfig, redis_client):
        self.cfg = config
        self.redis = redis_client

    async def generate_explanation(self, lesson_id: str, prompt: str) -> dict:
        cache_key = f"explain:{lesson_id}:{hashlib.sha256(prompt.strip().encode()).hexdigest()[:16]}"
        if cached := await self.redis.get(cache_key):
            return {"source": "redis_cache", "payload": cached}

        try:
            # Primary path: self-hosted fine-tuned Qwen behind OpenAI-compatible endpoint
            payload = await self._call_endpoint(self.cfg.qwen_base_url, prompt)
            await self.redis.set(cache_key, payload, ex=60 * 60 * 24)
            return {"source": "self_hosted_qwen", "payload": payload}
        except (httpx.TimeoutException, httpx.HTTPStatusError):
            # Overflow path: keep student experience alive during sudden GPU spikes
            payload = await self._call_endpoint(self.cfg.fallback_base_url, prompt)
            return {"source": "commercial_fallback", "payload": payload}

    async def _call_endpoint(self, base_url: str, prompt: str) -> str:
        async with httpx.AsyncClient(timeout=self.cfg.timeout_seconds) as client:
            res = await client.post(
                f"{base_url}/v1/chat/completions",
                json={"model": "qwen-edtech-ft", "messages": [{"role": "user", "content": prompt}]},
            )
            res.raise_for_status()
            return res.json()["choices"][0]["message"]["content"]
```

## 06 · Outcome

- **Migrated production explanation traffic** off commercial APIs to a self-hosted, fine-tuned Qwen deployment with zero student-facing downtime.
- **Replaced variable per-token bills** with predictable fixed hosting costs while improving Arabic response times via streaming + Redis caching.
- **Maintained reliability under peak traffic** through automated circuit-breaker failover.

## 07 · What I'd Do Differently Next Time

> Our initial cache keys relied on exact normalized hashes of the student prompt, which missed semantically equivalent phrasing (e.g., two Arabic ways of asking why a formula applies). Adding lightweight embedding similarity lookup in Redis before dispatching to the GPU would raise the cache hit ratio further and reduce peak GPU utilization during exam weeks.
