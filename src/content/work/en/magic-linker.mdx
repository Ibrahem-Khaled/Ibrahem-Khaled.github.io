## 01 · Context

Magic Linker connects suppliers, distributors, and independent retail shops across Yemen with both B2B wholesale buyers and B2C consumers. A single buyer frequently adds items from three or four different merchants into one cart, expects to pay once in their preferred currency (USD, SAR, or local settlement), and expects independent delivery tracking per store.

At the same time, each merchant needs an isolated view of their own orders, stock, and net payout after platform commissions — without ever seeing another merchant's pricing or customer data.

## 02 · Constraints

- **Regional payment fragmentation:** No single payment processor covers all regional and international cards cleanly, requiring simultaneous integration with **Stripe**, **PayPal**, and **Moyasar**.
- **Unreliable mobile networks:** Buyers and medical/general suppliers in Yemen often browse on intermittent connections; duplicate checkout taps and webhook retries are normal, not edge cases.
- **Single-codebase mobile delivery:** Shipping a responsive Android/iOS experience alongside the web storefront under a lean engineering budget.

## 05 · Key Engineering Decisions & Trade-offs

| Decision | Alternatives Considered | Why This Won |
|---|---|---|
| **Parent Order + Vendor Sub-Order Split Schema** | Flat `order_items` table with `vendor_id` only | A flat table breaks down when Vendor A ships on time while Vendor B cancels an item and triggers a partial refund. Separating `orders` (payment envelope) from `sub_orders` (fulfillment + settlement unit) keeps partial refunds and vendor statuses clean. |
| **Payment Gateway Strategy Adapter** | Direct SDK calls inside checkout controllers | Stripe, PayPal, and Moyasar have different currency precision rules, callback flows, and webhook signature formats. Isolating them behind a single `PaymentGatewayContract` kept checkout logic gateway-agnostic and testable. |
| **Immutable Ledger Entries for Commissions** | Storing a mutable `vendor.balance` integer column | Updating a balance column directly leaves no audit trail when a dispute happens. Recording append-only `ledger_entries` (credit, commission fee, payout) guarantees every cent reconciles. |

## 06 · Idempotent Payment Webhook Guard (Excerpt)

Payment gateways retry webhooks aggressively when networks hiccup. Every webhook event is verified and processed inside a single atomic guard keyed by `(gateway, external_event_id)`:

```php
declare(strict_types=1);

final class ProcessPaymentWebhookAction
{
    public function handle(string $gateway, string $eventId, string $orderRef, int $paidMinor): void
    {
        DB::transaction(function () use ($gateway, $eventId, $orderRef, $paidMinor): void {
            // Unique index on (gateway, external_event_id) makes duplicate retries harmless
            $alreadyProcessed = WebhookEvent::query()
                ->where('gateway', $gateway)
                ->where('external_event_id', $eventId)
                ->lockForUpdate()
                ->exists();

            if ($alreadyProcessed) {
                return;
            }

            WebhookEvent::create([
                'gateway' => $gateway,
                'external_event_id' => $eventId,
                'processed_at' => now(),
            ]);

            $order = Order::where('reference', $orderRef)->lockForUpdate()->firstOrFail();

            if ($order->status === OrderStatus::Paid || $order->total_minor !== $paidMinor) {
                throw new PaymentMismatchException("Order {$orderRef} failed integrity check.");
            }

            $order->markPaid();
            SettleVendorCommissionsJob::dispatch($order->id)->afterCommit();
        });
    }
}
```

## 07 · Outcome

- Shipped **both web storefront** ([magiclinker.com](https://magiclinker.com/)) and **Android mobile app** on [Google Play](https://play.google.com/store/apps/details?id=com.magiclink.medstore).
- Unified multi-vendor checkout across **Stripe, PayPal, and Moyasar** with automated commission settlement and zero cross-vendor data leakage.
- Enabled independent supplier onboarding, real-time buyer-merchant messaging, and multi-governorate order workflows.

## 08 · What I'd Do Differently Next Time

> Early in the rollout, currency conversion rates were fetched on demand during checkout, which introduced occasional latency spikes on slower links. Moving FX rates to a scheduled Redis snapshot updated every 15 minutes — stamped immutably onto each `order` record at creation time — eliminates external network dependencies from the critical checkout path.
