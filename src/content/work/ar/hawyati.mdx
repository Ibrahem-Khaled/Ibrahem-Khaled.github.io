## 01 · السياق والمشكلة

ساحات الميناء الجاف القريبة من ميناء جدة الإسلامي تستقبل حركة مستمرة من الحاويات الجافة والمبردة (Reefers) والفارغة وحاويات الصيانة. الاعتماد على الجداول التقليدية وحده يصعّب على مشرفي الساحة والعملاء رؤية كثافة التكديس، حركة الرافعات الجسرية (RTG)، أو متابعة درجات حرارة الحاويات المبردة لحظياً.

توليت المسؤولية الهندسية الكاملة للمنظومة — من تصميم قواعد البيانات ومنطق تخصيص الخانات ثلاثية الأبعاد، إلى بوابة العملاء ثنائية اللغة (عربي/إنجليزي) وبناء التوأم الرقمي التفاعلي **HAWYATI-YARD-TWIN** حتى الإطلاق الفعلي.

## 02 · القيود الهندسية

- **رسم آلاف الحاويات داخل المتصفح بسرعة 60fps:** دون إجبار موظفي التشغيل على تثبيت برامج مكتبية ثقيلة.
- **منع تصادم الخانات تماماً:** يستحيل أن يقوم مشرفان أو بوابتان بتخصيص حاويتين مختلفتين على نفس الإحداثي الفيزيائي `(yard_id, bay, row, tier)` في نفس اللحظة.
- **وضوح تشغيلي ثنائي اللغة:** واجهة عربية أصيلة لفريق التشغيل في جدة، مع تبديل فوري للإنجليزية لخطوط الشحن والعملاء الدوليين.

## 04 · أهم القرارات الهندسية والمقايضات

| القرار | البدائل المدروسة | لماذا كان هذا الخيار الأصح |
|---|---|---|
| **الرسم بالـ Instancing (`InstancedMesh`) في Three.js** | إنشاء Mesh منفصل لكل حاوية، أو خريطة 2D ثابتة | رسم آلاف الحاويات كعناصر منفصلة ينهار بالأداء بسبب كثرة الـ Draw Calls. تقنية Instancing ترسم التكديس بالكامل في عدد محدود جداً من استدعاءات GPU مع ثبات 60fps وتلوين لحظي لحالة كل حاوية (جافة، مبردة، فحص). |
| **فهرس مركب + قفل متشائم (`lockForUpdate`)** | فحص توفر الخانة في الكود قبل الإدخال | الفحص في PHP ثم الإدخال في استعلام ثانٍ يفتح ثغرة Race Condition في ساعات الذروة. القفل الصفي داخل `DB::transaction()` مع التحقق من وجود الطابق السفلي يضمن سلامة فيزيائية 100%. |
| **بث التغييرات عبر Redis Event Stream** | إعادة جلب خريطة الساحة بالكامل كل عدة ثوانٍ | سحب حالة 12,000 خانة بشكل متكرر يستهلك الباندويث ويسبب تقطّعاً في المشهد. بث تغييرات الحركة فقط يبقي شريط العمليات اللحظية (`[INSPECTION OK]`، `[COOLED] -18.2°C`) فورياً وخفيفاً. |

## 05 · نموذج من كود تخصيص الخانة الذري

مقتطف مبسّط لطبقة الحماية التي تمنع تكديس حاوية في الطابق الثالث إذا كان الطابق الثاني أسفلها فارغاً، وتمنع التصادم عند التزامن:

```php
declare(strict_types=1);

final class AllocateYardSlotAction
{
    public function execute(string $containerIso, int $bay, int $row, int $tier): YardSlot
    {
        return DB::transaction(function () use ($containerIso, $bay, $row, $tier): YardSlot {
            $column = YardSlot::query()
                ->where('bay', $bay)
                ->where('row', $row)
                ->lockForUpdate()
                ->get()
                ->keyBy('tier');

            if ($tier > 1 && !$column->has($tier - 1)) {
                throw new DomainException("Cannot stack at tier {$tier}: supporting tier is empty.");
            }

            if ($column->has($tier) && $column[$tier]->occupied_by !== null) {
                throw new DomainException("Slot B{$bay}-R{$row}-T{$tier} is already occupied.");
            }

            $slot = YardSlot::updateOrCreate(
                ['bay' => $bay, 'row' => $row, 'tier' => $tier],
                ['occupied_by' => $containerIso, 'status' => 'stacked', 'stacked_at' => now()]
            );

            YardTelemetryEvent::dispatch($slot);

            return $slot;
        });
    }
}
```

## 07 · ما الذي سأطوره بشكل مختلف في الإصدار القادم

> في الإصدار الأول للواجهة، يظهر شريط العمليات اللحظية داخل حاوية تمرير قد تُظهر Scrollbar أفقياً على بعض شاشات Windows، كما يتحمل مشهد WebGL مباشرة عند الفتح. في التحديث القادم سأستبدل الشريط بحركة CSS نظيفة بدون Scrollbar، وأحمّل مشهد الـ 3D تدريجياً خلف لقطة أولية ثابتة لتحسين الأداء على الأجهزة الضعيفة.
